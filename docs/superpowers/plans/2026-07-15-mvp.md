# PSBT Interop Lab MVP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Build an application-ready proof that runs one successful Core-to-Rust PSBT workflow and one synthetic reproduction of the BDK Python 2.3.1 finalization regression.

**Architecture:** A strict TypeScript CLI launches language-native adapters through a versioned JSONL protocol. Bitcoin Core 31.1 supplies controlled regtest UTXOs and final transaction policy checks; a Rust adapter signs BIP174 PSBTv0 fixtures; a frozen Python adapter exposes the affected BDK finalizer. Every transition is stored locally in a replayable artifact.

**Tech Stack:** Node.js 22/24, TypeScript 7, Ajv, Commander, Vitest, Bitcoin Core 31.1, Rust 1.97, rust-bitcoin 0.32.101, Python 3.13, bdkpython 2.3.1, Docker Compose.

## Global Constraints

- All signing is restricted to generated regtest outpoints and the openly documented test key with scalar value one.
- Bitcoin Core has no public-network connectivity and its RPC port binds only to host loopback.
- Adapter processes are launched without a shell, have bounded JSONL messages, bounded stderr, and per-request timeouts.
- Core 31.1 `createpsbt` produces PSBTv0. Its `version` RPC argument selects transaction version 2;
  it does not select the PSBT format version. The suite verifies PSBTv0 on the wire.
- No arbitrary PSBT signing command, hosted service, database, hardware device, or public compatibility score is included.
